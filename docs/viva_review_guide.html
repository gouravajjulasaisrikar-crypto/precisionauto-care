1. Project Summary in 4–5 Lines (The Elevator Pitch)

"Sir, PrecisionAuto Care is an enterprise automotive fleet maintenance platform built on a Java 21 and Spring Cloud microservices architecture.
It automates the workshop repair lifecycle and features an intelligent Collision Elimination Engine that prevents service bay double-bookings with automated conflict detection.
The backend utilizes Netflix Eureka for service discovery, an API Gateway for centralized routing, and OpenFeign for inter-service communication across 6 independent services.
When a technician completes a repair, the system automatically logs diagnostic history and generates a real-time, tax-calculated invoice (Labor + Parts + 10% Tax).
The platform enforces zero-trust JWT authentication with Role-Based Access Control across Customer, Technician, and Admin roles."

2. Theoretical Purpose: What Real-World Problem Does It Solve?

In commercial fleet operations (logistics, delivery companies, corporate transport), vehicle downtime equals financial loss. This platform eliminates 3 key operational bottlenecks:

  • Physical Bay Constraint Elimination: Workshops have limited hydraulic lift bays (BAY-1, BAY-2, BAY-3). Manual scheduling results in double-booking collisions. The platform mathematically prevents overlapping reservations using an automated collision avoidance algorithm returning HTTP 409 Conflict.
  • Compliance & Diagnostic Audit Trail: Fleet regulations require audit records for all repairs. Every completed service immutably logs technician ID, date, diagnostics, and replaced parts into a centralized vehicle ledger.
  • Automated Dynamic Financial Settlement: Eliminates manual accounting delays. The instant a repair is marked complete, labor and parts costs are aggregated with 10% tax into an itemized, payable invoice.

8. Collision Occurrence Code & Technical Implementation

1. Service Layer Implementation (Where the check happens):

// File: BookingService.java (Lines 44-51)
List<Booking> collisions = bookingRepository.findByBayIdAndServiceDateAndStatusNot(
        targetBay, serviceDate, "CANCELLED"
);

if (!collisions.isEmpty()) {
    throw new IllegalStateException("Collision Detected: " + targetBay +
            " is already booked for " + serviceDate + ". Please choose another bay or time.");
}

2. Controller Layer Implementation (Mapping to HTTP 409 Conflict):

// File: BookingController.java (Lines 27-38)
try {
    Booking booking = bookingService.scheduleBooking(request);
    return ResponseEntity.status(HttpStatus.CREATED).body(booking);
} catch (IllegalStateException e) {
    return ResponseEntity.status(HttpStatus.CONFLICT).body(Map.of(
            "status", 409,
            "error", "Booking Collision",
            "message", e.getMessage()
    ));
}

What have you used for it? (4 Key Technical Answers for Faculty):

  1. Spring Data JPA Derived Query: Used findByBayIdAndServiceDateAndStatusNot(bayId, date, "CANCELLED") in BookingRepository to query bay occupancy without writing raw SQL.
  2. REST Standard HTTP 409 Conflict: Returned HttpStatus.CONFLICT (409) instead of generic errors to signify that the request conflicts with current state of server resources.
  3. Java 21 Streams & Predicates: When a user leaves bay blank, Java Streams filter unoccupied bays from ALL_BAYS = List.of("BAY-1", "BAY-2", "BAY-3").
  4. ACID Transaction Isolation: Annotated with @Transactional to prevent race conditions during concurrent bookings.

11. Multi-Factor Authentication (Email + Password + OTP) Security Architecture

Q: How does the Email + Password + Mail OTP authentication work?

Review 2 Security Enhancement: To adhere to institutional Zero-Trust security guidelines, identity verification now uses email-based principal identification combined with mandatory email OTP verification before a signed JWT session is issued.

Two-Step Verification Pipeline:

  1. Factor 1 (Email & Password Credentials): User submits their enterprise email (e.g., customer@precisionauto.com, technician@precisionauto.com, admin@precisionauto.com) and BCrypt-hashed password + Canvas CAPTCHA challenge.
  2. Factor 2 (Email OTP Token): Upon credential validation, auth-service dispatches a cryptographically random 6-digit one-time authorization code to the registered email address with a 120-second TTL.
  3. Verification & Session Issuance: User inputs the 6-digit code received in their email (or clicks the Auto-Fill from Mail button). The API Gateway issues the signed HMAC-SHA256 JWT bearer token granting dashboard access.

Backend Implementation:

  • UserRepository.java: findByEmail() and findByUsername() derived queries.
  • AuthService.java: generateOtp(username) and verifyOtp(username, enteredOtp) with concurrent expiration tracking.
  • AuthController.java: POST /auth/otp/send and POST /auth/otp/verify REST endpoints.
  • server.js (Node / SMTP Engine): Integrated with Google SMTP (smtp.gmail.com:587 TLS) to dispatch real, live verification emails directly to the user's inbox in real time.

What to say to Sir:

"Sir, for Review 2 we upgraded our identity layer to use enterprise email credentials paired with Two-Factor Authentication (2FA). When a user submits their email and password, the API Gateway authenticates the principal and triggers an automated OTP dispatch to the user's email inbox. Only when the 6-digit email code is verified does the service mesh issue the signed JWT session, providing complete Zero-Trust protection."
